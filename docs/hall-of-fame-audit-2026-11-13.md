### 공동 저장 신뢰성 수정

- API가 실제 `ok`를 반환해야 전송 대기열 항목 삭제 및 '저장 완료' 표시.
- `paused`, `bad_score`, `no_class`, `too_many` 등 거절 및 네트워크 오류에서는 기록 보존, 재시도, 오류 표시.
- 오프라인 대기 300건 초과 시 오래된 기록을 조용히 삭제하지 않고 경고.
- 학급 번호/연결의 유효성, 개인 AI 대전 제외 조건 유지.
- 구 화면 캐시가 현재 순위로 오인되지 않도록 상태 표시.

## 붕어빵 팀 기록 의미

- 2인/4인 협동은 한 팀의 동일 매출을 각 팀원 개인 기록으로 복제하지 않는다. **참가자 번호 배열 + 팀 매출 + 고유 요청 키**를 한 행으로 저장한다.
- 팀 내부의 순서는 정렬해서 동일 팀을 일관되게 집계하며, 참여자 목록을 명예의 전당에 표시한다.
- 학생 선택은 4인 이상도 가능하도록 공유 선택 UI 확장; 태블릿 화면에서는 기존과 같이 2인 초과 모드가 숨겨지는 정책 유지.
- 팀 구성원의 번호를 삭제하면 해당 학생이 포함된 팀 기록도 연관 제거되도록 교사 삭제 RPC 처리.
- 참가자 식별이 없는 '손님' 플레이는 명예의 전당에 올리지 않는다.
- `shop_solo`는 5일 완료 기준으로, 실패로 재시도한 날의 매출은 해당 5일 기록에 더하지 않는다.
- 협동별 점수판은 개인별이 아니라 팀별 최고 매출을 기준으로 정렬한다.

## 과거 기록과 코인 지급

- 과거 `stairs`, `jump`, `shop` 값에는 모드 정보가 없다. 자동 추정·재배치 금지. '이전 기록' 종목으로 별도 보존.
- 이전 종목의 기존 주간 결산 경로를 유지한다.
- **새로 분리된 8개 종목(`stairs_*`, `jump_*`, `shop_*`)은 명예의 전당에는 표시되지만 주간 코인은 자동 지급하지 않는다.** 특히 4인 팀 전원 지급과 다수 종목 신규 분리 시 지급 중복 위험이 있으므로 후속 보상 정책 합의 전 보류.
- 명예의 전당에서 표시되는 '챔피언'은 새 종목 점수를 포함할 수 있으므로 코인 보상 결과와 구별해야 한다.

## DB 검증

- 기존 데이터를 건드리지 않는 컬럼·인덱스 추가와 RPC 변경만 적용.
- `begin / do / rollback` 시험으로 2인/4인 팀 저장, 중복 요청 멱등성, 번호 중복 거절, 일·주간 집계에서 팀원 배열 조회를 검증.
- 같은 방식으로 무한의 계단 및 호자 점프 신규 모드 4종 입력·조회 확인.
- 시험 데이터 모두 롤백됨 (시험 요청 키 잔존 0건).
- GitHub Actions 작업 브랜치에서 `build.py` 빌드 및 합쳐진 JS 구문 검사 시행.

## 검증 경계 / 후속 권고

- 기록이 없는 종목은 실제 사용자 플레이 사례가 없을 수도 있으므로, 저장 건수가 0이라는 것만으로 오류라고 판정하지 않는다.
- 브라우저와 교실 대시보드 사이의 실제 코인 차감·환불·인원 선택·입력, 전체화면·터치 UI는 정적 점검 및 CI만으로 최종 확인되지 않는다. 실제 수업 장비에서 1·2·4인 각 한 경기 후 HOF에서 확인하는 E2E가 필요하다.
- 현재 서버는 class code를 아는 호출을 신뢰하고 `hof_add_record`를 통해 기록한다. 추가 부정 기록 방지는 별도 보안 설계가 필요하다.
